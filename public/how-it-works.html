How it works

This site runs a personal AI assistant on Netlify Server. Its owner talks to it on Telegram or in the console on this site, and it remembers things about them, sends reminders, watches pages for changes and searches the web. This page explains how it's built, for anyone thinking about deploying their own or changing it.

The parts

Everything runs on Netlify, with no AI API keys to manage:

  • Netlify Server runs the assistant. It's a Hono app on one small instance, with Telegram's webhook, the console's API, a run queue and the agent loop.
  • Netlify Database (Postgres) keeps the memory, schedules and conversation history, and also every message, run and reply on its way through.
  • The AI Gateway provides Claude and web search.
  • A scheduled function wakes the server up when something is due.

The server keeps nothing that matters in memory. Everything it needs to pick up where it left off is in the database.

The life of a message

  1. Telegram sends your message to the server's webhook. The server saves it in the database together with the run that will answer it, in one transaction, and only then tells Telegram it got it. A message from the console goes into the same queue.
  2. The run starts the agent loop. Claude gets the conversation so far and your notes, and can call tools (memory, schedules, web search, reading a page) for up to 10 rounds.
  3. Before each model call and each search, the assistant sets aside the most that call could cost, so it stays under the daily spending cap. It settles the real cost afterward.
  4. The reply goes into an outbox in the database, and from there to Telegram. In the console, it streams into the page as it's written.

Deploys, crashes and idle stops

A server instance can go away at any point: a new deploy replaces it, it crashes, or it stops after being idle for a few minutes. The run queue in src/queue.ts makes sure every message still gets an answer:

  • A run holds a lease that it renews every 30 seconds. If its instance dies, another instance picks the run up after the lease runs out (90 seconds).
  • Whatever a run already did, like saving a note or creating a schedule, is recorded, so a retry doesn't do it again.
  • If a reply might have gone out already, the retry says so.
  • When a new deploy goes live, the old instance stops taking new work right away, and gets 60 seconds to finish what it's running.

We tested each of these on the platform: killing the instance mid-run, deploying mid-run, streaming through a deploy, schedules on an idle server, and answering from cold. On a cold start, a Telegram message was recorded 1 second after it was sent. The details are in docs/checks.md in the repo.

Waking up for schedules

Only a request starts a server that has stopped. So a scheduled function (netlify/functions/wake.mts) runs every minute, checks the database for anything due, and calls the server only when there's work. That way the server can stop when it's idle and still send your 8:00 brief.

Safety

  • It has one owner. Telegram pairs only through a one-time link from the console, and the console needs the password, with failed attempts throttled.
  • The assistant can't act in the world beyond messaging its owner, remembering things and scheduling.
  • Text from the web or from a forwarded message can't change anything on its own. Once a run has read such text, changes to notes, schedules or the persona become proposals, which the owner confirms with a button. Scheduled jobs can read and report, but never change anything.
  • Only the published production deploy acts. An old deploy's permalink or a deploy preview gets a 409, instead of touching the data or sending messages.
  • No tool reads environment variables or files, so the tokens and the password never reach the model.

What it costs

The model is Claude Sonnet 5.5 by default, and a web search costs about $0.007. There's a daily spending cap, $2 by default, which the owner can change in Settings.

Deploy your own

The code is on GitHub, at netlify-templates/netlify-server-telegram-bot. Its README has the setup steps: deploy, set the console password (an Agent Run can help with that), and connect a Telegram bot. For the platform itself, see the Netlify Server docs.
